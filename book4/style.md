# 翻译与排版规范（务必逐条遵守）· 第四卷 持久存储

## 0. 任务
把一份英文 Markdown 源（原书《Operating Systems: Principles and Practice》第四卷：Persistent Storage，第 11–14 章）
逐段翻译为中文，并按下面的规则写成 Typst 片段文件。这是**全文翻译**，不是摘要：
源文件里的每一段、每一条列表、每一个例子、每一条边栏、每一道习题、每一张图表的题注都要译出，不得删减、合并或另加内容。

## 1. 语言与文风
- 译文是**教材/讲义体中文**：准确、平实、术语统一，句子可读性优先，不要逐词硬译，也不要口语化。
- 长英文复句可拆成两三个中文短句；英文的 "we" 译作“我们”，泛指读者时可省略主语。
- 术语首次出现时用「中文（English）」形式，例如“文件系统（file system）”“索引节点（inode）”；同一术语后文不再重复英文。
  术语译法**必须**与 `book4/glossary.md` 一致。
- 不译：代码、函数名、变量名、系统与产品名（UNIX、Linux、FFS、NTFS、ZFS、FAT、POSIX、SCSI、SATA）、缩写（MTTF、MTTR、RAID、DMA、LBA、TCQ、SSD）。
- 书名、论文名保留英文原文，可加中文说明。
- 数字与单位：`10 毫秒`、`4 个处理器`、`99%`（数字用半角，数字与汉字之间不留空格）。
- 标点：中文全角（，。；：？！、）；破折号用 `——`，省略号用 `……`；
  引号用 “ ” 和 ‘ ’；括号用（）；英文缩写或代码紧邻时可用半角括号，但整段保持统一。
- 英文原文中的举例、幽默、比喻要保留语气，不要删。

## 2. Markdown → Typst 的固定映射

| 源（Markdown） | 目标（Typst） |
|---|---|
| `# *11. File Systems: Introduction and Overview*` | `#chapter(11, "文件系统：导论与概述", en: "File Systems: Introduction and Overview")`，紧随其后的一行斜体引语用 `epi: [...]` 传入 |
| `## 11.1 The File System Abstraction` | `#sect("11.1", "文件系统抽象")` |
| `### 11.3.1 API and Performance` | `#subsect("11.3.1", "应用程序接口与性能")` |
| `#### 无编号小标题` | `#subsubsect("小标题")` |
| `## Exercises` | `#exercises[ + 第一题 + 第二题 ]`（题目用 `+ ` 编号） |
| `- 项目` | `- 项目`（保持不变） |
| `1. 项目` | `+ 项目` |
| `*斜体*` | `_斜体_`（Typst 的强调；模板会把中文强调渲染成楷体） |
| `**粗体**` | `*粗体*` |
| `` `code` `` | `` `code` ``（不变） |
| `[[EXAMPLE]] 正文` | `#example[ 正文 ]` |
| `[[EXAMPLE]] **标题。** 正文` | `#example(tag: "例")[ *标题。* 正文 ]` |
| `[[ANSWER]] 正文` | `#answer[ 正文 ]` |
| `[[FIG:11.2:image00301.png:caption]]` | `#fig("11.2", "image00301.png", [译文题注])` |
| `[[FIG::image00353.png:]]`（无编号插图） | `#figimg("image00353.png")` |
| `[[INFIG:image00313.jpeg]]`（边栏内的照片） | `#align(center)[#image("../figures/image00313.png", width: 72%)]`（章文件在 `chapters/` 下，直接引用图片要写 `../figures/`） |
| `::: aside 标题` … `:::` | `#aside("译文标题")[ … ]` |
| `[[CODE:14.2:caption]]` + 代码围栏 | `#code(num: "14.2", cap: [译文题注], lang: "c")[ ```c … ``` ]` |
| `[[TAB:11.1:caption]]` + 竖线表 | `#tbl("11.1", [译文题注], ((…),(…)), header: ([…],[…]))` |
| `[[MATH]]` + `$…$` 块 | **原样保留**（Typst 数学，已写好，不要改动、不要翻译） |

要点：
- `#chapter` 只在**每个源文件出现 `# *N. 章名*` 时**使用；其余文件从 `#sect` 开始。
- 图号、表号、代码图号**沿用原书编号**，不要重排。
- `#tbl` 的第三个参数是“行数组”，每个单元格是 `[…]` 内容块：
  ```typst
  #tbl("11.1", [持久存储设备的物理特性如何影响操作系统的存储抽象设计], (
    ([可靠性], [块大小 512 B], [以块为单位读写]),
  ), header: ([目标], [物理特性], [设计含义]))
  ```
  若原表首行只是跨栏的粗体表名（与题注重复），删去该行。
  若原表没有表头，省略 `header:`。列宽不合适时可加 `columns: (auto, 1fr)`。
- **无编号的 `[[TAB::]]`**：这类表多为把公式单独排成表格的“公式表”（如 `磁盘访问时间 = 寻道时间 + 旋转时间 + 传输时间`）。
  译成一行居中的 Typst 数学即可，例如：
  ```typst
  #align(center)[$"磁盘访问时间" = "寻道时间" + "旋转时间" + "传输时间"$]
  ```
  若确实是数据表（如两列对照的指令表），照常写成 `#tbl(none, none, (...), header: (...))`。
- 表格单元格里出现 `|` 时，源文件里写作 `\|`，译文里直接写 `|`。
- **列表项里夹图**：源中形如
  ```
  4. **非对称。** 正文……
     [[FIG:13.11:image00324.png:……]]
     后续正文……
  ```
  表示插图夹在该条目的两段文字之间。译文照此顺序写：条目正文、`#fig(...)`、后续正文，
  且 `#fig(...)` 与后续正文都要**相对条目正文缩进两个空格**（Typst 据此判定它们仍属于该条目；
  完全不缩进会让列表中断、后续条目重新从 1 编号）。`#fig` 前后各留空行。
  若插图在条目末尾，则把 `#fig(...)` 直接写在条目正文之后（同样缩进两格）。
- **习题的子问题**：源中以 `- （a）…` 形式出现，译文写成缩进的 `- （a）…` 子列表，保留字母标记。
- 代码块**原样保留**（缩进、注释、字符串都不改）。**不译代码中的任何内容**。

## 3. Typst 书写注意
- 正文中若出现 `#`、`$`、`@`、`~`、`<`、`>`、`\`、`_`、`*` 等特殊字符，必须转义（前加 `\`）或放进反引号。
  中文里常见的是 `#`（如 “C#”）、`$`（如 “$5”）、`%`（`%` 在 Typst 中安全），务必检查。
  特别注意：路径 `/home/alice/a.txt`、`#doc.txt#`、`*` 通配符、下划线 `_` 都要处理。
- 空行分段；一段一行写完即可（不必手动折行）。
- 列表项之间不要空行。
- 数学：`$O(n^2)$`、`$T_1$`、`$C_(i,j) = sum_(k=0)^(N-1) A_(i,k) B_(k,j)$` 用 Typst 数学。
  源文件中的 `~{下标}` 与 `^{上标}` 是上下标标记：`T~{1}` → `$T_1$` 或 `T#sub[1]`。
- 不要使用 `#import`（首行除外）、`#set`、`#show` 等全局设置；模板已提供样式。
- 不要写 `#pagebreak()`，章节会自动换页。

## 4. 交叉引用
- `Figure 11.2` → `图 11.2`；`Table 11.1` → `表 11.1`；`Chapter 13` → `第 13 章`；
  `Section 13.3` → `13.3 节`；`Exercises 13.7` → `习题 13.7`。
- 图/表编号后不加标点，直接接说明文字。
- 注意：原书正文偶有把**表**称作 Figure 的笔误（如正文说 `Figure 11.1`、`Figure 11.6`、`Figure 12.9`、`Figure 12.10`、`Figure 13.8`，
  而实际是表 11.1、表 11.6、表 12.9、表 12.10、表 13.8）。遇到这类明显错配，按实际图表译作“表 X.Y”。
