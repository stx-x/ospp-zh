# 翻译与排版规范（务必逐条遵守）

## 0. 任务
把一份英文 Markdown 源（原书《Operating Systems: Principles and Practice》第二卷：Concurrency）
逐段翻译为中文，并按下面的规则写成 Typst 片段文件。这是**全文翻译**，不是摘要：
源文件里的每一段、每一条列表、每一个例子、每一条边栏、每一道习题都要译出，不得删减、合并或另加内容。

## 1. 语言与文风
- 译文是**教材/讲义体中文**：准确、平实、术语统一，句子可读性优先，不要逐词硬译，也不要口语化。
- 长英文复句可拆成两三个中文短句；英文的 "we" 译作“我们”，泛指读者时可省略主语。
- 术语首次出现时用「中文（English）」形式，例如“线程（thread）”“临界区（critical section）”；同一术语后文不再重复英文。
  术语译法**必须**与 `book/glossary.md` 一致。
- 不译：代码、函数名、变量名、系统与产品名（UNIX、Linux、Apache、Google Earth、x86、POSIX）、缩写（TCB、RCU、FIFO、SJF、DMA）。
- 书名、论文名保留英文原文，可加中文说明。
- 数字与单位：`10 毫秒`、`4 个处理器`、`99%`（数字用半角，数字与汉字之间不留空格）。
- 标点：中文全角（，。；：？！、）；破折号用 `——`，省略号用 `……`；
  引号用 “ ” 和 ‘ ’；括号用（）；英文缩写或代码紧邻时可用半角括号，但整段保持统一。
- 英文原文中的举例、幽默、比喻要保留语气，不要删。

## 2. Markdown → Typst 的固定映射

| 源（Markdown） | 目标（Typst） |
|---|---|
| `# *4. Concurrency and Threads*` | `#chapter(4, "并发与线程", en: "Concurrency and Threads")`，紧随其后的一行斜体引语用 `epi: [...]` 传入 |
| `## 4.1 Thread Use Cases` | `#sect("4.1", "线程的使用场景")` |
| `### 4.1.1 Four Reasons…` | `#subsect("4.1.1", "使用线程的四个理由")` |
| `#### 无编号小标题` | `#subsubsect("小标题")` |
| `## Exercises` | `#exercises[ + 第一题 + 第二题 ]`（题目用 `+ ` 编号） |
| `- 项目` | `- 项目`（保持不变） |
| `1. 项目` | `+ 项目` |
| `*斜体*` | `_斜体_`（Typst 的强调；模板会把中文强调渲染成楷体） |
| `**粗体**` | `*粗体*` |
| `` `code` `` | `` `code` ``（不变） |
| `[[EXAMPLE]] 正文` | `#example[ 正文 ]` |
| `[[ANSWER]] 正文` | `#answer[ 正文 ]` |
| `[[FIG:4.1:image00388.png:caption]]` | `#fig("4.1", "image00388.png", [译文题注])` |
| `::: aside 标题` … `:::` | `#aside("译文标题")[ … ]` |
| `[[CODE:4.6:caption]]` + 代码围栏 | `#code(num: "4.6", cap: [译文题注], lang: "c")[ ```c … ``` ]` |
| `[[TAB:6.1:caption]]` + 竖线表 | `#tbl("6.1", [译文题注], ((…),(…)), header: ([…],[…]))` |

要点：
- `#chapter` 只在**每个源文件出现 `# *N. 章名*` 时**使用；其余文件从 `#sect` 开始。
- 图号、表号、代码图号**沿用原书编号**，不要重排。
- `#tbl` 的第三个参数是“行数组”，每个单元格是 `[…]` 内容块：
  ```typst
  #tbl("6.1", [不同处理器数量下的临界区开销], (
    ([1], [28], [28]),
    ([2], [35], [112]),
  ), header: ([处理器数], [不相交的锁], [同一把锁]))
  ```
  若原表首行只是跨栏的粗体表名（与题注重复），删去该行。
  若原表没有表头，省略 `header:`。列宽不合适时可加 `columns: (auto, 1fr)`。
- 表格单元格里出现 `|` 时，源文件里写作 `\|`，译文里直接写 `|`。
- 代码块**原样保留**（缩进、注释、字符串都不改），只在必要时把注释译为中文？——**不译代码中的任何内容**。

## 3. Typst 书写注意
- 正文中若出现 `#`、`$`、`@`、`~`、`<`、`>`、`\`、`_`、`*` 等特殊字符，必须转义（前加 `\`）或放进反引号。
  中文里常见的是 `#`（如 “C#”）、`$`（如 “$5”）与 `%`（`%` 在 Typst 中安全），务必检查。
- 空行分段；一段一行写完即可（不必手动折行）。
- 列表项之间不要空行。
- 数学：`$O(n^2)$`、`$T_1$`、`$C_(i,j) = sum_(k=0)^(N-1) A_(i,k) B_(k,j)$` 用 Typst 数学。
  源文件中的 `~{下标}` 与 `^{上标}` 是上下标标记：`T~{1}` → `$T_1$` 或 `T#sub[1]`。
- 不要使用 `#import`、`#set`、`#show` 等全局设置；模板已提供样式。
- 不要写 `#pagebreak()`，章节会自动换页。

## 4. 交叉引用
- `Figure 4.1` → `图 4.1`；`Table 6.1` → `表 6.1`；`Chapter 5` → `第 5 章`；
  `Section 4.2` → `4.2 节`；`Exercises 4.7` → `习题 4.7`。
- 图/表编号后不加标点，直接接说明文字。

## 5. 交付
- 只写指定的 `.typ` 文件，不要改动模板、不要创建其它文件（自检用的临时文件用完请删除）。
- 写完后自查：`cd book && typst compile <临时文件> out.png` 能通过（可跳过，但请仔细检查括号与 `#` 转义）。
- 不要输出解释性文字，不要在文件里写“以下是译文”之类的话。

## 6. 示例（源 → 译文）

源：
```
## 4.2 Thread Abstraction

A thread is a single sequence of instructions. Threads share the address space.
As Figure 4.3 shows, each thread has its own stack.

::: aside Why "Unpredictable Speed"?
Threads run at unpredictable speed because the scheduler can preempt them.
:::

[[FIG:4.3:image00390.png:Two threads sharing an address space but with private stacks.]]
```

译文：
```typst
#sect("4.2", "线程抽象")

线程是一个单一的指令序列。同一进程内的线程共享地址空间。如图 4.3 所示，每个线程拥有自己的栈。

#aside("为什么“速度不可预测”？")[
线程的运行速度之所以不可预测，是因为调度器可以在任意时刻抢占它。
]

#fig("4.3", "image00390.png", [两个线程共享同一地址空间，但各自拥有私有的栈。])
```
